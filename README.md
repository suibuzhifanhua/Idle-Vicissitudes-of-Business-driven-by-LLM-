# 商海浮沉 — 使用说明

> **Author:** Fisheep.L

> LLM 驱动的放置式经营模拟游戏。在虚构的商业都市里，从一无所有到商业帝国，每一步都由你决策。

## About

A browser-based idle business simulation game powered by local LLM (Ollama). Start from nothing — choose your origin, build businesses across cities, manage employees, negotiate with NPCs, trade stocks, acquire real-world assets, auction collectibles, and climb your way to a commercial empire. Every decision matters, and the LLM generates dynamic narratives, business news, competitor intelligence, and market sentiment analysis.

**Tech Stack:** Vanilla JS + Ollama API + Python (local server)
**Codebase:** core.js 4,610 lines (165 functions) · ui.js 2,897 lines (97 functions) · llm.js 429 lines (33 functions) · settings.js 752 lines (23 functions)
**Play:** 运行 `启动游戏.bat` 或 `python server.py`，浏览器访问 `http://localhost:8765`

## 快速开始

### 方式一：通过 .bat 文件启动（推荐）

双击 **`启动游戏.bat`**，游戏将自动在浏览器中打开。

### 方式二：手动启动本地服务器

> ⚠️ **必须通过 HTTP 服务器打开**，直接双击 `index.html` 会导致 LLM 功能因浏览器安全限制而无法使用。

```bash
# 默认只监听 127.0.0.1，不会把存档 API 暴露给局域网
python server.py

# 自定义主机和端口
python server.py --host 127.0.0.1 --port 8765

# 只有确需局域网访问时才添加允许的主机名/IP
python server.py --host 0.0.0.0 --port 8765 --allow-host 192.168.x.x

# 然后在浏览器中访问：
http://localhost:8765
```

### 关闭游戏

关闭 `启动游戏.bat` 所在窗口即可停止服务器。页面内的退出按钮受浏览器安全策略限制，不一定能自动关闭标签页。

### 运行验证

```bash
npm test
npm run test:api
npm run test:all
```

`npm test` 在假 DOM 中运行游戏核心；`npm run test:api` 用临时 SQLite 数据库验证本机服务。验证失败时进程会返回非零退出码。

> 本机若无独立 Node，可用 Qoder 自带运行时：`ELECTRON_RUN_AS_NODE=1 "Qoder CN.exe" verify-gameplay.mjs`。

### 仓库与发布

- 仓库根目录的 `.gitignore` 已排除运行时与私密产物：`saves/`（SQLite 存档及 WAL，含玩家进度）、`*.db*`、`*.pre-sqlite-*`、`__pycache__/`、`*.pyc`。
- 入库内容为纯源码与资源：JS/CSS/HTML、`server.py`/`db.py`、测试脚本、`config-*.js`、`data-*.js`、`启动游戏.bat`、`bgm.wav`、`README.md`。**存档与数据库不进仓库**，克隆后首次启动会自动初始化。
- `config.js` 已从根目录归档为 `_legacy/config.js`，`index.html` 不再加载它。
- 更新远端时按常规 `git add -A && git commit && git push` 即可；本仓库保留提交历史，不使用 force push。

## LLM 配置

游戏深度集成本地 LLM，用于生成**事件叙事、NPC 对话、员工背景故事、商业新闻、竞争对手情报、市场情绪分析、动态事件、里程碑叙事**等内容。没有 LLM 时游戏仍可正常进行，但叙事体验会大幅减弱。

### 默认配置

| 参数 | 默认值 |
|------|--------|
| LLM 接口地址 | `http://localhost:11434`（Ollama） |
| 模型 | `qwen3.5:4b` |
| Temperature | 0.85（固定值，`CONFIG.LLM_TEMPERATURE`） |
| 最大输出 Token | 2048（固定值，`CONFIG.LLM_MAX_TOKENS`） |

设置面板已取消「创意度」和「最大输出」两个滑块，取值统一在 [config-game.js](config-game.js) 的 `LLM_TEMPERATURE` / `LLM_MAX_TOKENS` 里改。之所以给到 2048：vLLM、Qwen3.5/3.8 这类带思考的模型会先把 token 预算花在 `reasoning` 上，预算小了只剩思考、没有正文，游戏里就会表现为“连不上/没输出”。

### 支持的提供商

游戏内 **⚙ 设置 → LLM设置** 可切换三种提供商，切换后会清空模型名，需重新填写或获取：

| 提供商 | 协议 | 地址默认值 | 需要 API Key |
|--------|------|-----------|-------------|
| **Ollama** | `POST /api/generate` | 留空即走 `/api/ollama` 代理 | 否 |
| **LM Studio** | `POST /v1/chat/completions` | `http://localhost:1234` | 否 |
| **自定义 OpenAI 兼容 API** | `POST /v1/chat/completions` | 用户填写 | 视端点而定 |

### 接入自定义 OpenAI 兼容端点（云端 API / 本地推理服务）

适用于 DeepSeek、阿里云百炼、智谱 GLM、Moonshot Kimi、OpenRouter、硅基流动，以及 vLLM、Ollama 的 OpenAI 兼容层等任何符合 `/v1/chat/completions` 协议的端点：

1. 游戏内 **⚙ 设置** → LLM 提供商 → **自定义 OpenAI 兼容 API**
2. 在 **🌐 常用服务商** 里选一个预设（会自动填入地址），或直接手填 API 地址
3. 填 **🔑 API Key**（点 👁 可显示；无需鉴权的端点可留空）
4. 点 **🔍 获取模型** 拉取 `/models` 列表并点选模型
5. 点 **🔗 测试连接** 验证（会真实生成一次，失败时显示上游返回的错误原因）
6. 点 **💾 保存并应用**，顶栏绿点亮起即接入成功

注意事项：

- **地址写法**：末尾缺版本段时自动补 `/v1`（如 `https://api.deepseek.com` → `.../v1`）；已带版本的保持原样（如智谱 `https://open.bigmodel.cn/api/paas/v4`）；不小心粘成完整的 `.../v1/chat/completions` 会自动截回 `.../v1`。省略协议时，`localhost`/`127.0.0.1` 按 `http` 处理，其余按 `https`。
- **CORS**：远端 API 不允许浏览器直连，所有自定义端点请求都由 `server.py` 的 `/api/relay?target=<url>` 转发。**改过 `server.py` 后必须重启游戏服务器**（先关掉原来的 `启动游戏.bat` 窗口再双击），否则会提示 `server.py 需重启以支持 /api/relay 转发`。
- **思考型模型**：vLLM 上的 Qwen 等模型会把推理放在 `reasoning` 字段、正文放在 `content`。只读 `content`；若某次 `content` 为空，错误信息会带上 `finish_reason`（`length` 即预算被思考占满）。`🔗 测试连接` 用 64 token 探测，遇到这种情况会显示「端点可用 · 本次未产出正文」而不是报失败。
- **API Key 存储位置**：只写本浏览器的 `localStorage`（键名 `shanghaifc_llm_key`），**不写入 `saves/` 存档数据库**，因此复制/分享存档不会带出密钥；换浏览器或清理站点数据后需重新填写。
- **转发安全**：`/api/relay` 只接受带本机会话令牌、且目标地址已由用户显式注册的请求。页面首次使用自定义端点时会通过 `/api/relay/config` 注册规范化后的 Base URL；未注册地址会返回 `relay_base_not_registered`。
- **本地服务防护**：所有 API 校验 Host、Origin、`Sec-Fetch-Site` 和一次性会话令牌；`saves/`、SQLite/WAL、Python 源文件及 dotfile 不再作为静态资源提供。改过 `server.py` 后必须重启服务器。
- **超时**：云端首字延迟可能较高，生成超时取 `CONFIG.LLM_GENERATE_TIMEOUT`（默认 120s），连通性检测超时 10s。

### 配置步骤（Ollama，推荐本地起步）

1. 确保已安装并运行 [Ollama](https://ollama.com/)
2. 拉取推荐模型：`ollama pull qwen3.5:4b`
3. 游戏内点击顶栏 **⚙ 设置** → 修改接口地址和模型名称
4. 顶栏左侧绿色圆点亮起表示 LLM 已连接

### LLM 功能开关

在设置面板中可以分别开启/关闭：
- **事件叙事**：随机事件的 AI 描述
- **员工背景**：招聘时生成员工故事
- **NPC 对话**：人脉 NPC 的 AI 台词
- **决策叙事**：重大决策的背景描述（新增）

### LLM 请求队列

内置请求队列管理，最大并发 **2** 个请求，自动降级和冷却机制，防止 Ollama 过载。

## LLM 增强功能

以下功能在 LLM 在线时自动激活，无需手动配置：

### 📰 商业新闻（每 20 Tick）
LLM 根据当前市场状态、玩家业务和竞争对手动态，自动生成商业快讯。在右侧事件日志区顶部以青色标签展示。

### 🔍 竞争对手情报（每 30 Tick）
LLM 分析竞争对手排名和市场份额变化，生成竞争情报简报。以紫色标签展示在事件日志区。

### 📊 市场情绪引擎（每 15 Tick）
LLM 综合分析游戏全局状态（资金、声望、业务、经济周期等），输出 **0-100 市场情绪指数**。仪表盘新增市场情绪卡片实时展示，情绪值影响股价波动幅度、事件触发概率和资产市场价格。

| 情绪区间 | 图标 | 标签 |
|---------|------|------|
| 80-100 | 🔥 | 极度乐观 |
| 65-79 | ☀️ | 偏乐观 |
| 45-64 | ☁️ | 中性 |
| 25-44 | 🌧️ | 偏悲观 |
| 0-24 | ❄️ | 极度悲观 |
实际调参建议
想要更稳定、可预测的游戏体验 → 降低 Temperature 到 0.3~0.5
想要更丰富、意外的游戏情节 → 提高 Temperature 到 0.9~1.2
觉得事件描述太短/太简略 → 提高 Max Tokens 到 500~800
担心 token 消耗/响应速度 → 降低 Max Tokens 到 150~200

### ⚡ AI 动态事件（每 25 Tick，30% 概率）
LLM 完全自主生成事件标题、描述和选项，不再依赖预定义事件表。极端市场情绪下触发概率提升至 50%。AI 事件效果由解析引擎自动映射为资金/声誉/压力数值。

### 🎯 决策叙事
决策事件卡片中新增金色斜体叙事框，LLM 为每次重大决策生成背景铺垫文字。

### 📜 里程碑叙事
达成资产里程碑或高级成就时，LLM 生成个性化叙事文字，取代固定文本。

### 🔗 叙事连续性
系统维护最近事件叙事摘要链，新事件叙事会参考之前的上下文，形成因果连贯感。

### 🧠 NPC 对话上下文注入
NPC 对话 prompt 自动注入最近游戏事件摘要，NPC 会评论玩家最近的商业举动，大幅提升对话沉浸感。

## 核心玩法

### 放置机制

游戏每 **30 秒**执行一次 Tick（游戏内约 1 小时），自动结算：
- 所有业务的收益与成本
- 员工薪资扣除与疲劳变化
- 压力自然衰减
- 忠诚度与声誉衰减
- 维护成本扣除
- 供应链状态更新
- 竞争对手市场份额变化
- 贷款利息扣除
- 子公司自动运营
- 经济周期波动
- 资产市场价格更新与拍卖结算
- LLM 商业新闻/情报/情绪/动态事件生成

### 时间系统

游戏内 24 个 Tick = 1 个游戏日。支持黎明/白天/黄昏/夜晚四个时段，影响业务收益。

### 天气系统

游戏包含 7 种天气类型，影响业务收入和事件触发：

| 天气 | 收入影响 | 事件倾向 |
|------|----------|----------|
| ☀️ 晴天 | 100% | 中性 |
| ☁️ 多云 | 100% | 中性 |
| 🌧️ 雨天 | 95% | 偏负面 |
| ⛈️ 暴风雨 | 85% | 危机 |
| 🌫️ 雾天 | 90% | 中性 |
| ❄️ 雪天 | 88% | 中性 |
| 🔥 高温 | 92% | 偏负面 |

### 季节与节日系统

游戏模拟一年 360 天四季轮回，包含 12 个节日（春节、元宵、清明、劳动、端午、七夕、中秋、国庆、双十一、双十二、元旦、圣诞），节日期间相关业务获得临时收益加成。

### 玩家属性

| 属性 | 说明 |
|------|------|
| 💰 资产 | 当前现金，低于 -50万 连续 8 个 Tick 将触发破产 |
| ⭐ 声誉 | 0-100，影响区域解锁、NPC关系和贷款利率 |
| 😰 压力 | 0-100，过高影响决策质量，积累触发负面事件 |
| 🤝 人脉 | 上限 100，社会关系网络值，影响合作机会 |
| 📊 市场情绪 | 0-100，LLM 分析输出，影响股价和事件触发 |

### 手动工作

点击中央区域的**手动拉项目**按钮（或按 `空格`）可立即获得一次性收益，但有 **20 Tick 冷却时间**，且有 8% 概率触发负面结果。25% 概率额外获得 1-2 人脉。

## 城市与区域

### 区域机制

每个区域同时拥有**增益加成**和**负面修正**，选择业务落地区域时需要权衡利弊：

### 升级系统

每个业务有 **10 个等级**，升级需满足：
1. 业务所在区域必须已解锁
2. 资金充足
3. 达到对应幕次要求
4. **满足前置条件（reqCond）**：部分高等级需要特定科技等级、NPC好感度或声誉

> 💡 不满足前置条件时，升级按钮会显示提示（如"需科技Lv2"、"需林教授好感40"）

### 维护成本

每 Tick 产生维护成本 = 业务收入 × 基础比例(2%) + 等级附加(0.5%/级)。业务等级越高，维护成本占比越大。

### 业务协同

同一区域或类型的多条业务线可产生**协同加成**，中央区域顶部会显示当前协同状态。

### 员工深度系统

- **疲劳度**：员工每 Tick 积累疲劳，疲劳过高影响效率和忠诚度，自然恢复
- **培训系统**：花费资金培训员工技能，最高 5 级
- **忠诚度**：随时间自然衰减，过低可能**主动离职**
- **Burnout**：长期加班触发过度劳累事件
- 解雇员工需支付赔偿
- **LLM 生成员工背景**：招聘时 AI 自动生成个性化员工故事

### 实习生转正系统

实习生入职后进入**实习期**，享受工资折扣，完成实习后自动转正：

| 参数 | 说明 |
|------|------|
| 实习期工资 | 正式工资的 **50%** |
| 实习时长 | **20 Tick**（约 10 分钟） |
| 转正属性加成 | 全属性 **+10** |
| 转正忠诚加成 | **+15** |
| 转正目标 | 根据属性权重自动匹配最合适的正式岗位 |

**转正匹配规则**：实习生成成时根据属性权重得分自动确定转正目标岗位（开发者/设计师/销售/分析师/管理者/律师/HR），UI 展示转正路径。实习期进度条实时显示，转正后徽章标识"✅ 已转正"。

> 💡 实习生招聘成本仅为正式员工的一半，是前期低成本扩张的有效手段。

### HR 统管模式

当员工数超过阈值（无 HR 时 8 人，有 HR 时 5 人），自动进入 HR 统管模式：
- 批量招聘（成本折扣 20%）、批量培训（成本折扣 30%）
- 工资折扣 5%
- 每 Tick 自动降低全员工疲劳值
- 自主维护各部门人数平衡和忠诚度

- **持有市值** 随 Tick 波动：趋势漂移 + 随机波动 + 市场情绪影响
- **下限保护**：市值不会低于购买价的 20%

### 操作入口

| 操作 | 触发方式 | 说明 |
|------|----------|------|
| 浏览市场 | 面板 `💎 资产` 或按 `8` | 8 件随机资产，每 12 Tick 刷新 |
| 购买资产 | 市场卡片点击「购买」 | 资金充足 + 槽位未满（上限 20） |
| 挂牌拍卖 | 我的资产点击「🔨 挂牌」 | 自定义要价，3-8 Tick 自动成交 |
| 取消拍卖 | 拍卖行中点击「取消」 | 撤回挂牌 |
| 紧急典当 | 我的资产点击「💸 典当」 | 即时回款，38%-55% 市值 |
| 仪表盘 | `💎 资产估值` 卡片 | 总市值 + 持有数量 |

### 拍卖机制

- 挂牌后可自定义要价，系统根据市场价评估成交概率
- 要价越接近市场价，成交概率越高（最高 95%）
- 偏离越大，成交概率越低（最低 15%）
- 未成交时自动延长等待并微调降价
- 成交后资金即时到账

### 托管集成

- **资金充裕时**（保留 30% 流动储备）：自动选购高趋势/低波动资产
- **资金窘迫时**（低于 2 倍单 Tick 支出）：自动典当市值最低的非拍卖资产救急

## 离线收益

关闭游戏后重新打开，系统会按**最近20个Tick的净收入均值**分段折算，不再直接套用最高毛收入：

| 离线时长 | 折算效率 |
|---|---:|
| 0–6小时 | 100% |
| 6–12小时 | 70% |
| 12–24小时 | 40% |
| 超过24小时 | 不再累计 |

- 结算依据：`netIncomeSamples` 中最近20个Tick的“毛收入 - 工资 - 维护”均值。
- 样本不足时回退到当前净收入，不读取瞬时最高倍率。
- 领取凭证一次性消费，领取后结算时间推进到本次离线结束点。
- 参数位于 [config-game.js](config-game.js) 的 `OFFLINE_EFFICIENCY_PHASES`。

### 反膨胀约束

- 自动/手动拉项目：每个游戏日前8次按正常收益，之后效率降为10%。
- 员工收入倍率：采用饱和曲线，配置上限为 `EMPLOYEE_MULT_SOFT_CAP: 5`。
- 全局收入倍率：前12倍正常保留，超出部分按65%边际继续衰减。
- 动态难度倍率：限制在0.8–1.2，持续35 Tick后自动过期。
- B2B合同：签约业务会按已承诺产能降低基础业务收入，避免合同与主业重复计算。
- 长时程验证：`npm run test:balance`，模拟1/24/72/720小时并输出富豪等级到达时间。

> 这些修改会让旧存档的扩张速度明显变慢，但不会改变已有资产数值。若希望保留旧曲线，可把上述配置调回更宽松值。

## 商业并购（M&A）系统

> 新增后期资金获取途径：与高好感 NPC 达成商业并购，获得一次性现金奖励 + 永久性持续收入。

### 触发条件

与任意 NPC 好感度 ≥ **60**，打开对话即出现「🤝 商讨并购事宜」按钮。

### 并购成本

```
成本 = NPC商业价值 × MA_BASE_COST_MULT × (1 + MA_FAVOR_DISCOUNT_MAX - 折扣)
折扣 = MA_FAVOR_DISCOUNT_MAX × (好感度 / 100)
```

| 好感度 | 成本倍数 | 说明 |
|--------|----------|------|
| 60 | ~1.33× | 最低可并购门槛 |
| 80 | 1.0× | 平价并购 |
| 100 | ~0.67× | 最高折扣（约 6.7 折） |

### NPC 商业价值

| NPC | 商业价值 | NPC | 商业价值 |
|-----|----------|-----|----------|
| 陈总 | 1,000 万 | 赵磊 | 500 万 |
| 小C | 800 万 | 金行长 | 600 万 |
| 张野 | 400 万 | 林教授 | 450 万 |
| 李处 | 200 万 | 孙秘书 | 180 万 |
| 王律师 | — | 苏姐 | 150 万 |
| 钱老板 | 300 万 | 吴教练 | 120 万 |
| 马记者 | 200 万 | | |

### 并购收益

| 收益类型 | 计算公式 | 说明 |
|----------|----------|------|
| 一次性现金 | 商业价值 × 15% | 并购完成后即时到账 |
| 持续收入 | 商业价值 × 0.8% × (好感/80) | 永久注入每 Tick 总收入 |

> 💡 好感度 80 时，持续收入达到最大值（商业价值的 0.8%/Tick）

### 限制与冷却

- 每个 NPC **只能并购一次**
- 并购后 **50 Tick** 冷却（同一 NPC 不可频繁操作）
- 资金不足或已达员工上限时无法并购

### 操作入口

1. 与好感 ≥60 的 NPC 对话
2. 点击「🤝 商讨并购事宜」
3. 确认并购成本与收益
4. 确认后完成并购，业务面板底部显示「🤝 已并购业务」列表

### 配置参数（config-game.js）

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `MA_BASE_COST_MULT` | 1.0 | 并购基础成本倍数 |
| `MA_FAVOR_DISCOUNT_MAX` | 0.5 | 好感满分时最大折扣（50% off） |
| `MA_LIQUID_BONUS_RATIO` | 0.15 | 一次性现金奖励比例 |
| `MA_REVENUE_RATIO` | 0.008 | 持续收入比例 |
| `MA_COOLDOWN_TICKS` | 50 | 并购冷却 Tick 数 |

## 扩展经营闭环

顶栏 **🧩 经营闭环** 和面板标签提供以下新系统。所有系统都有确定性离线规则，LLM 只从已注册模板中选择方案，不能自行发明金额或效果。

- **节日经营战役**：节日前出现经营窗口，可选择备货锁价、营销冲量或弹性排班；执行期联动供应稳定性、品牌口碑和员工状态，结束后生成履约复盘。
- **NPC人情债**：正向合作可累积每人最多2点人情，危机时请求贷款展期、情报、反挖角或备用供应商；完成后需在规定 Tick 内偿还反向请托。
- **对手意图预告**：挖角和价格战前3 Tick出现模糊征兆，可购买情报确认目标，也可提前部署反制。
- **B2B长期合同**：按业务产能接收订单，合同包含数量、周期、预付、质量与违约赔偿；供应中断和安全库存会直接影响交付率。
- **产品定位**：切换性价比、高端品牌或技术领先，并调整价格带、研发和营销预算；倍率进入实际业务收入。
- **多供应商组合**：主供/备供按成本、交期和稳定性分配，安全库存可自动缓冲断供。
- **子公司章程**：选择现金牛、扩张、研发或平衡，设置分红、再投资和风险偏好；周期结束生成实际与预测偏差报告。
- **董事会任期**：可选开启任期，每届有两个可能互相冲突的目标；长期放置存档不会被强制结束。
- **统一待办中心**：聚合事件、贷款、合同、报价、对手征兆、人情债、子公司报告和董事会到期，按剩余时间排序。
- **决策预览与后验**：事件选择后保存基线，6/12 Tick后记录收入、现金、声誉、压力和市场份额变化。
- **托管预演**：查看未来10 Tick准备执行什么、原因和现金储备判断；预演不修改状态。

扩展数值集中在 [config-extensions.js](config-extensions.js)，模板候选集中在 `EXTENSION_TEMPLATES`。当前实现没有修改既有业务、股票、贷款或里程碑常数；新玩法数值仍需结合长期存档做人工平衡。

## 存档说明

- 游戏每 **8 Tick** 自动保存一次；页面隐藏或关闭时还会尝试写入最新快照
- 存档只保存在服务器端 SQLite 数据库 `saves/game.db`，`saves/` 已禁止静态下载
- 同一槽位按单调递增 `saveRevision` 串行写入，服务器会拒绝旧快照，降低网络重试导致的进度回滚
- 预加载状态未知时会阻止新建游戏，避免把服务异常误判成“没有存档”
- JSON 旧存档逐文件迁移并回读校验，成功后重命名为带时间戳备份，不再直接删除
- 支持**多槽位存档**（slot 1/2/3），可在设置中管理
- 支持**离线收益**：关闭游戏后重新打开，系统会计算最多 **24小时** 的离线收益；领取凭证一次性消费，结算时间原子推进
- 支持**存档导入/导出**，导入会复用与读档相同的严格校验并等待服务器确认
- SQLite 使用 WAL；停服做一致性备份时，应停止 `server.py` 后同时备份 `game.db`、`game.db-wal`、`game.db-shm`，或优先使用 SQLite backup API

> ⚠️ 存档只存在服务器本地，删除 `saves/` 里的数据库文件即永久删除，请谨慎操作。

## 常见问题

**Q：LLM 离线了，游戏还能玩吗？**
A：可以正常游玩所有核心功能。事件叙事、NPC对话等使用预设模板代替，商业新闻/竞争情报/市场情绪/动态事件等 LLM 增强功能暂停。

**Q：游戏卡顿了怎么办？**
A：减少同时运行的业务数量，或关闭不必要的面板。

**Q：为什么资产一直减少？**
A：检查员工总薪资、业务运营成本和维护成本是否超过了收益。也可考虑典当部分资产救急（按 `8` 进入资产面板）。

**Q：业务升级按钮为什么是灰色的？**
A：升级需要满足前置条件（reqCond），鼠标悬停在按钮上可查看具体要求（如科技等级、NPC好感、声誉等）。

**Q：如何触发 LLM 生成的特殊事件？**
A：保持 LLM 在线状态，随机事件触发时（约每 **6 Tick** 检查一次，基础概率 **25%**）会调用 LLM 生成叙事。每 **25 Tick** 有 30% 概率触发完全由 LLM 即时生成的动态事件。

**Q：存档在哪里，如何备份？**
A：存档在游戏目录下的 `saves/` 文件夹，直接复制 JSON 文件即可备份。也可通过设置面板的导入/导出功能迁移存档。

**Q：游戏时间和现实时间的关系？**
A：每 **30 秒**现实时间 = 游戏内约 1 小时；每 24 个 Tick = 1 个游戏日。

**Q：托管模式为什么没触发？**
A：请确认在设置面板中勾选了「🔛 启用全自动托管（主开关）」。仅勾选子策略开关不会自动启用托管。

**Q：为什么收入比预期少？**
A：可能原因：竞争对手抢占市场份额、供应链断裂、经济周期处于萧条/危机、维护成本扣除。检查市场份额和供应链状态。

**Q：子公司是什么？**
A：解锁多个城市后，可将非当前城市转为子公司自动运营，获得 60%-80% 的收益分成，无需手动管理。

**Q：天气和节日影响游戏吗？**
A：会。不同天气影响业务收入（-5% ~ -15%），节日期间相关行业有额外加成（+10% ~ +40%）。经济周期也会显著影响全局收益。

**Q：资产如何买卖？**
A：按 `8` 进入资产中心。市场每 12 Tick 刷新 8 件随机资产，可直接购买。已购资产可挂牌拍卖（自定义要价，3-8 Tick 自动成交）或紧急典当（即时回款 38%-55% 市值）。

**Q：市场情绪是什么？**
A：LLM 每 15 Tick 分析游戏全局状态输出的 0-100 指数，影响股价波动、资产价格、事件触发概率。仪表盘实时展示。

**Q：资产价格为什么会波动？**
A：资产持有市值受三方面影响：市场情绪起伏、趋势漂移（长期升值/贬值）、随机波动。极品资产（史诗级）通常长线升值，而数字藏品等高波动品类短期波动剧烈。

**Q：典当和拍卖有什么区别？**
A：拍卖需要等待 3-8 Tick，有机会以接近市场价甚至更高价卖出；典当即时回款，但只能拿到市场价的 38%-55%（相当于割肉救急）。

**全新功能——商业并购（M&A）系统：**

- 新增 **NPC 商业并购机制**：与好感度 ≥60 的 NPC 对话时出现「🤝 商讨并购事宜」按钮
- 并购成本动态计算：`NPC商业价值 × (80 ÷ 好感度)`，好感越高越便宜（最高约 6.7 折）
- 并购收益双重回报：
  - 一次性现金奖励 = 并购成本 × 15%，即时到账
  - 持续收入 = NPC 商业价值 × 0.8% × (好感÷80)，**永久注入每 Tick 总收入**
- 12 位 NPC 各自拥有独立商业价值（150 万 ~ 1000 万），配置于 `config.js` 的 `NPC_BUSINESS_VALUE`
- 冷却限制：同一 NPC 并购后 50 Tick 冷却，防止刷钱
- UI 集成：「业务」面板底部新增「🤝 已并购业务」列表，实时显示持续 Tick 收入
- 收入系统集成：并购收入注入 `calcTotalIncome()`，参与所有现有修正（压力、声誉、技能、市场份额等）
- 5 个可配置参数（`MA_BASE_COST_MULT` / `MA_FAVOR_DISCOUNT_MAX` / `MA_LIQUID_BONUS_RATIO` / `MA_REVENUE_RATIO` / `MA_COOLDOWN_TICKS`）
