# v1.14 永恒篇 8640h 自然仿真报告

**目的**：验证 v1.14 两项修复——① 后期随机事件通道死锁（dedup 集饱和，幕 6-9 事件流枯竭）② `G.eventCount` 死计数器——并实测真结局（幕 9）后 1e13~1e14+ 资产区间的留存曲线与永恒篇事件触发。
**命令**：`SEED=1 SIM_HOURS=8640 SIM_ONLY=scheduled node balance-simulation.mjs`（主验收）+ 默认 horizons 720h 双跑 ×2（基线指纹）；真跑 doTick，mulberry32 种子 1。8640h = 1,036,800 tick（一个游戏年）。
**日期**：2026-11-16

## 背景：两层根因

8640h 首跑（仅加永恒篇事件、未修 dedup）暴露：720h 后 7920h 窗口内**仅 34 条随机事件**、永恒篇 4 条仅触发 3 次（其中 3e13 门槛的理事会 0 次）——「真空」不是事件不够，是**通道死了**：

| 层 | 根因 | 证据 |
|----|------|------|
| 通道层（P1） | `_firedEventIds` 去重集 50 槽 + 幕 6-9 事件池仅 7/9/11/13 条：池被集占满后，加权选单 100% 命中「近期已触发」候选、被 `fireEvent` 静默浪费 | 微验证：act9 池 13 条 + 饱和 dedup 集，20000 次加权选单 **100% 落空**；幕 6/7/8/9 池 7/9/11/13 全 <50 |
| 计数器层（P1） | `G.eventCount` 唯一自增点在 `core.js` 不可达 fallback；唯一漏斗 `EventSystem.fireEvent` 只推 `eventHistory` 从不计数 | event_10/30/50/100 四成就永不可达、`event_100` 的 `decisionBonus` 从未生效、统计面板恒 0 |

**修复**：
- 通道层：`EventSystem.getFireable(candidates)` 剔除 dedup 阻塞候选；**全阻塞时按「最早触发时刻」逐个破缺释放**（调用方已先做 cooldown 过滤，被释放者冷却必已完整过期，重触发安全）。core.js `tryFireEvent` **仅当候选数 ≤50**（dedup 集容量、死锁必要条件）才走新路径——幕 1-5 池 102/148/168/155/96 恒 >50 走原路径，**前段 RNG 逐位不变**（初版无条件过滤实测使 720h 基线 83,936,469,154→88,516,762,801 漂移 +5.5%，故加门控）。
- 计数器层：计数收拢到 `fireEvent` 唯一漏斗（纯状态写入，零新增 Math.random）。

## 1e15 clamp 说明

harness 在 `G.money > 1e15` 时钳制为 1e15（防 float 精度问题，`balance-simulation.mjs`）。8640h 终值 999,999,958,257,414 已在 clamp 下沿——**这是仿真工件，不是游戏数值上限**：游戏内 1e14 即 RANK_TIERS 封顶档「永恒商神」，其后再无头衔/幕次/事件门槛依赖更高资产（永恒篇 1e14 档为最高门槛）。真实玩家越过 clamp 区间的经济行为由 v1.13 已定的「自由经营 + 永恒篇 + NG+」定位承接。
